# Correctness analysis of the original allocation code

This analysis covers `shiny/app/GroupTherapyPatientRandomization.R` (the algorithm) and `shiny/app/GroupTherapyPatientAllocationWebApp.Rmd` (the app). It is based on reading the code, on runs of the original code in R 3.5.2 with the exact 2020 package versions (`tests/reference.R`), and on the original app running in Docker (`tests/shiny_test.js`). Test cases are named `cNN_…` (in `tests/cases`, generated by `tests/gen.R`); the example data sets are in `docs/examples`.

## Verdict

For "well-behaved" input, the algorithm does what its documentation says. Well-behaved means:
- both files list the covariates in the same order;
- every covariate value of a new patient also occurs among the existing patients;
- integer spots;
- at least as many new patients as spots.

Under those conditions it:
1. makes a random initial allocation;
2. runs a correct steepest-descent search over pairwise exchanges of patients between arms, minimizing the chi-square of the combined strata × arm table;
3. picks the best configuration found with probability 0.8 (otherwise another configuration from the search trace);
4. maps the stratum counts back to patients correctly, with a random order within each stratum.

The JS port reproduces all of this bit for bit.

Outside those conditions there are real bugs. Several are silent, so the app gives a wrong allocation without any warning. There is also one serious security problem.

| # | Issue | Kind | Effect |
|---|---|---|---|
| 1 | The 'Available spots' text is run with `eval(parse())` | **security bug** | Anyone who can open the page can run R code on the server. That includes reading other users' uploaded patient files in the shared R process. Verified: an expression with `Sys.getenv()` was evaluated. |
| 2 | Spots are never re-optimized when there are more spots than new patients | **algorithmic bug** (design) | How many new patients each arm gets is fixed by the initial random draw. In `more-spots-than-patients`, the result was the global optimum in only 3% of 2000 seeds. |
| 3 | Covariate columns in a different order in the two files | **bug, silent** | The tables of existing and new patients are added cell by cell with mismatched strata, so the wrong imbalance is minimized (`c08`). |
| 4 | A new patient's covariate value does not occur among the existing patients | **bug, silent** | The patient becomes an NA stratum. The row matching then shifts: other patients lose their arm (NA) and a spot appears without a patient (`c09`). |
| 5 | The patient-ID selector defaults to the first column and has no "none" option | **bug, silent** | Without an ID column, the first covariate is dropped from the balancing and shown as the "ID" (`c05` config 1). |
| 6 | Decimal spots (e.g. `A = 2.5`) are accepted | bug | `rep()` truncates but `sum(k)` does not, so a patient gets arm NA (`c20`). |
| 7 | Error handling (`error = traceback`, `finaly`), out-of-range seed | bug | After an error the allocation tab only says "An error has occurred" and the download fails. A seed ≥ 2^31 disconnects the session. |
| 8 | Arms must already have patients | limitation | An arm without existing patients cannot get spots, and the very first patients of a trial cannot be allocated. |
| 9 | The "wait" list is a column of the chi-square | design question | Who waits is chosen so that the wait list resembles the overall sample, not to optimize balance among the treatment arms. |
| 10 | The 20% "randomness" is a uniformly chosen worse imbalance *value* from the trace | design question | When the best class is not chosen, the imbalance was on average 2.05× (max 5.0×) the local optimum in one example, and 1.30× (max 1.93×) in another. |

The remaining points below are harmless quirks.

## 1. `ftable_imbalance()`

```r
E = outer(rowSums(O), colSums(O)) / sum(O) + 0.0001
X2 = sum((O-E)^2 / E)
chi2*X2 + WSS*V + BSS*mvar        # chi2 = 1, WSS = BSS = 0
```

- This is Pearson's X² of the **combined** table: existing plus new patients, strata (the full cross-classification of all covariates) × arms (+ wait). Minimizing it balances the whole trial, which is reasonable for minimization. Two caveats:
  - It balances the joint strata, not the covariate margins as Pocock–Simon does. With 3 covariates of 2–3 levels there are 18 sparse cells.
  - Strata that have no patients at all still count (each contributes about 0.0001 per arm).
- **+0.0001 on E:** prevents 0/0 for empty strata and for the empty "wait" column of the existing patients. The bias is tiny and the same for all candidates. Harmless.
- **WSS / BSS:** the variances `V` and `mvar` are computed and multiplied by 0. That is wasted work, and it would turn the imbalance into `NA` (and crash the search) only for a table with a single column, which cannot occur because "wait" is always a column. Harmless.
- **The "wait" column is treated as an arm (issue 9).** When there are more patients than spots, the chi-square also tries to make the wait list look like the rest of the sample. That may or may not be intended. Balance among the treatment arms is no longer the only goal.
- **Floating point:** `sum()` accumulates in 80-bit long double, so `new_imb < best_imb` depends on that. With a plain double sum, 34 of the 39 R 3.5.2 test configurations give a different trace (checked by mutation testing). The JS port therefore emulates long double.

## 2. Initial random allocation

```r
K = c(k, wait = pmax(0, nrow(new) - sum(k)))
newAlloc = cbind(new, arm = factor(sample(rep(names(K), K))[1:nnew], levels = levels_wait))
```

- **`sum(k) <= nnew`:** every spot is used and the rest goes to `wait`. Correct.
- **`sum(k) > nnew`:** a random subset of the spots is used. This is fine as a starting point, but see section 3: the subset is never changed afterwards.
- **Decimal spots (issue 6):** the check `\w+\s*=\s*\d` accepts `A = 2.5`. `rep()` truncates 2.5 to 2, `wait = 5 − 3.5 = 1.5` becomes 1, and 4 spots for 5 patients leave one patient with arm `NA` (`c20`: patient 1013 has no arm).
- **No new patients:** `[1:0]` selects one element, so the result is the error "arguments imply differing number of rows". Minor.

## 3. Local search (`generatePatientAllocation3`)

- **Moves.** A move exchanges one patient of stratum `i` in arm `col_from` with one patient of stratum `j` in arm `col_to` (i ≠ j). That keeps both the row sums (patients per stratum, as it must) and the **column sums** (new patients per arm) unchanged. There is no move that puts a patient into an unused spot. Consequences:
  - When `sum(k) > nnew`, the number of new patients per arm is fixed by the random initial draw and is never optimized (issue 2).
  - In `docs/examples/more-spots-than-patients` (5 patients, spots 4/4/4) the arm totals ranged over 18 patterns, from 2/2/1 to 4/0/1, depending only on the seed.
  - The local optimum equalled the global optimum (brute force over all 105 feasible count tables) in 59 of 2000 seeds (3%). The mean final X² was 2.77, against a global optimum of 1.82.
  - When `sum(k) <= nnew` the arm totals are fixed by `k` anyway. In `two-covariates-waitlist` and `closed-arm-zero-spots` the local optimum was the global one in 2000 of 2000 seeds.
- **`if (i >= j) next`** is correct. The loops over `col_from` / `col_to` cover both directions, so every unordered pair of strata is considered exactly once. Exchanges within a stratum (i = j) do not change the table. `non_zero_rows` is a random permutation, but the skip compares row *indices*, so the random order affects only the evaluation order. Ties are therefore broken by the first strictly better candidate in a random order.
- **Reset of `new_counts`:** `new_counts = keep_new_counts` at the top of the innermost loop starts every candidate from the current allocation. After the loops, `new_counts` is replaced by `best_counts_sofar`. Correct.
  - The loop counter `k` shadows the argument `k`. This is harmless, because `K` has already been computed.
- **Steepest descent:** all neighbours are evaluated, the strictly best one is taken, and the search stops when there is no strict improvement. This is a correct steepest descent, and it terminates. It finds a **local** optimum only, with no restarts.
  - In `three-covariates-large` (24 new patients, 18 strata, 4 arms), 300 seeds gave 5 different local optima. The best was found in 35% of runs; the worst had a 1.7% higher X². In practice the difference is small.
- **`sample(which(rowSums(new_counts) > 0))`** has the `sample()` pitfall: when only stratum 4 has new patients, `sample(4)` returns a permutation of 1:4 (`c14`: `which` = 4 → `non_zero_rows` = 2 3 4 1). The empty strata are skipped by the `< 1` checks, so this only changes the number of random draws, and with them the rest of the random stream. Harmless, but reproduced exactly.
- **Covariate column order (issue 3).**
  - `current_counts` takes the existing file's column order (`sex, agegroup`), and `new_counts` takes the new file's order (`agegroup, sex`, in `c08`).
  - `current_counts + new_counts` adds the two tables cell by cell. When the dimensions agree (2·3 = 3·2), strata are silently mismatched. Otherwise the result is the error "non-conformable arrays".

## 4. Trace

`all_counts` starts with the initial allocation. Each iteration then appends **every** candidate it evaluated:
- non-improving candidates are included;
- duplicates are included. For example, the reverse exchange back to the previous allocation is in the next iteration's neighbourhood, and one allocation can be reached from several others.

The final allocation is in the trace: it was the chosen candidate of the last improving iteration, or it is entry 1 when nothing improved. In `c10_large` the trace has 2400 entries after 10 iterations.

## 5. `sampleAllocation()`

- **Two definitions of `f`:** the second overwrites the first (dead code). With `a = predictability = 0.8`, `f` gives P = 0.8 to the lowest imbalance value and 0.2/(m − 1) to each of the other m − 1 distinct values of `round(imb, 10)` in the trace.
  - The default `a = exp(-.2231436)` is never used.
  - The weighted draw (`sample(y, 1, prob = p.y)`) runs through `ProbSampleNoReplace` with one `unif_rand()`, the same in R 3.5 and 3.6 and independent of `sample.kind`.
- **Meaning of the 20% (issue 10).**
  - Every worse imbalance *value* that occurs in the trace is equally likely, however bad it is, so the "random" choice can be the worst configuration of the first neighbourhood.
  - The candidates come only from the search path, not from all valid allocations.
  - Measured over 2000 seeds: the best class was chosen in 80.3% / 78.6% / 79.1% of runs (expected 80% plus small chance effects). Otherwise the chosen X² was on average 2.05× (max 5.0×) the optimum in `more-spots-than-patients`, 1.30× (max 1.93×) in `two-covariates-waitlist` and 1.14× in `closed-arm-zero-spots`.
  - This differs from the usual biased-coin minimization, where with p = 0.8 the best arm is chosen per patient and otherwise a random arm.
- **Within a class**, one trace *entry* is drawn uniformly. Configurations that appear more often (duplicates) are therefore more likely. Quirk.
- **Classes are built with `cut()`:** breaks lie at the midpoints `x + min(diff(x))/2`, which separates the distinct rounded values correctly.
  - `g` classifies the *unrounded* values. Only when two rounded values differ by exactly 1e-10 could an unrounded value fall into the neighbouring class. A class could then have no members, and `sample_from(integer(0), 1)` would fail with "invalid first argument". Theoretical.
- **Early return:** when there is only one distinct value, `attr(allocation, 'trace')[1]` is a list of one element, so `[[1]]$counts` works and returns the initial allocation. Every candidate had the same imbalance, so this is fine.
- **`sample_from()`** correctly avoids the length-1 pitfall for `y` and for `which(g == k)`.

## 6. `matchPositionsPatients()`

- **Correct when no stratum is NA.**
  - `positions` (one row per allocated spot) and `patients` are both sorted by the covariates in factor-level order (dplyr 0.8.5 `arrange_all` / `arrange_at`), so the k-th patient and the k-th spot belong to the same stratum.
  - The `full_join` on `rowname` plus the covariates pairs them one to one.
  - `mutate(patient_id = sample(patient_id))` per stratum then shuffles which patient of a stratum gets which arm. `patient_id` is the character row name, so `sample()` has no length-1 pitfall here; a group of one patient uses one random draw and keeps its patient.
- **Unseen covariate values (issue 4).** A new patient whose covariate value does not occur among the existing patients becomes `NA` (`factor(new[[nm]], levels(the_df[[nm]]))`). It is not counted in `new_counts`, so there is one spot fewer than there are patients, and the two sorted lists no longer line up. In `c09`:
  - the two PTSD patients get arm NA, which is understandable;
  - patient 1017 (male, anxiety) also gets NA;
  - a row with no patient but arm B is appended.

  This also happens early in a trial, whenever some level has not yet occurred among the existing patients.
- **`arrange(patient_id)`** sorts the row-number strings as text ("1", "10", "11", "2", …), so the output is not in file order. Cosmetic.

## 7. `groupTherapyAllocate()` input checks and output

- **Patient-ID column (issue 5):** the Rmd's `selectInput` has no empty choice and selects the first column of the new file. Without an ID column, that first covariate is removed from both data sets (`select(-patient_id_column)`) and its values become the "ID" column (`c05` config 1: the output columns are `sex, agegroup, arm`, with sex as the ID, and sex was not balanced).
  - The JS version offers "(none)" in addition, to make the intended use possible. It still defaults to the first column, as in the original.
- **`if (length(extra_name) > 1 | extra_name != "arm" | is.null(the_df$arm))`**, with the non-short-circuit `|`:
  - with no difference in columns (the existing file lacks `arm`, or both files have `arm`), the condition is `logical(0)` and R stops with the cryptic "argument is of length zero";
  - with more than one difference, R warns "the condition has length > 1" and uses the first element, which is `TRUE`.

  The outcome is always an error, but the messages are poor. `is.null(the_df$arm)` (partial matching `$`) is redundant.
- **`names(k)` are checked against the values of `arm` (issue 8):** an arm without existing patients cannot receive spots, and an empty existing file (the first patients of a trial) always fails. Names such as `wait` or duplicates are not checked.
- **Missing checks:** nothing checks that new covariate values exist among the existing patients (issue 4) or that the columns are in the same order (issue 3).
- **Output formatting:** `as.matrix(as.data.frame(...))` formats numeric columns to a common width. Numeric IDs 9 and 10 become `" 9"` and `"10"`, and in R 3.5 logical values become `" TRUE"`, so the CSV can contain leading spaces. The JS version reproduces this. R 3.6 dropped the padding for logical values; with sample.kind "Rejection" the JS version follows R 3.6.
- **Combined output:** `bind_rows(existing, alloc)` appends the ID column at the end when only the new file has one (`c06`). Fine.

## 8. The Rmd (Shiny app)

- **`eval(parse())` of the 'Available spots' text (issue 1).**
  - The `grepl()` check is not anchored: each comma-separated piece only has to *contain* `name = digit`. Text such as `A = 1, B = 0*nchar(Sys.getenv("HOME")) + 2` passes and is executed (verified in the Docker image: the Debug tab shows B = 2).
  - All sessions of an app share one R process, so injected code can read other users' uploads in `tempdir()`.
  - The JS port does not evaluate code. It accepts exactly `name = number` pairs and otherwise shows "Error in 'Available spots'".
- **Uploading the existing-patients file** replaces the spots text with `"<arm>  = 0, …"`, so all new patients go to `wait` until the user edits it. Quirk. The JS version does the same.
- **Seed (part of issue 7).**
  - Two observers set `val$rSeed`. The first uses `try(as.integer())` and tests `inherits(rSeed, "error")`, which is never true because `try()` returns a "try-error".
  - The second observer overwrites the value with the raw number. `set.seed()` truncates a non-integer seed.
  - A seed outside the integer range makes `set.seed()` fail inside an observer, which disconnects the session (verified).
  - The JS version shows the error instead.
- **`tryCatch(…, error = traceback, finaly = print(…))` (part of issue 7).**
  - `finaly` is a misspelling of `finally`. It becomes a handler for a condition class that never occurs, and its value is evaluated immediately (`list(...)`), so the message is printed *before* the computation.
  - `error = traceback` returns the condition object, which becomes `val$alloc`. The allocation tab then shows Shiny's generic "An error has occurred. Check your logs…" (`renderTable` cannot convert the condition).
  - "Download All" fails with "invalid numbers in 'quote'", and the browser gets a cancelled `downloadFile.txt`.
  - Only the Debug tab shows the message. The JS version shows the message in the allocation tab and disables the download.
- **The 'Randomness' slider** is disabled (min = max = 0.2). The predictability is fixed at 0.8 = 1 − 0.2. `reactiveValues(predicatbility = 1, patien_id = NULL)` contains misspellings, but they are never read. Harmless.
- **Computed twice:** the allocation is computed in the observer and again in the Debug `renderPrint`, with the same seed and therefore the same result. Harmless.
- **`renderTable(..., options = list(scrollY …))`:** the options are DataTables options and are ignored by `renderTable`. Harmless.
- **No patient data on disk:** uploads and the rendered document go to the R session's `tempdir()`. Nothing is written next to the Rmd (verified in the container), and the log contains only messages. R removes `tempdir()` when the process ends (`app_idle_timeout 1800`). `shiny/deploy/grouptherapy-cleanup.cron` covers processes that were killed.

## Recommendations (not applied: the original is kept verbatim)

1. **Replace `eval(parse())`** with a parser for `name = integer`, and reject decimals.
2. **Add single moves** (a patient to a free spot or to `wait`) to the local search, or choose the arm totals by optimization.
3. **Match covariates by name:** for example `ftable(..., row.vars = names(new))` for both tables.
4. **Build factor levels from both files**, so unseen covariate values are counted instead of becoming NA.
5. **Offer "(none)"** as patient-ID choice.
6. **Return errors as messages**, not as the condition object; validate the seed.
7. **Leave `wait` out of the chi-square**, if balance among the arms is the goal.
8. **Allow arms without existing patients**, using the arm levels from `k`.
